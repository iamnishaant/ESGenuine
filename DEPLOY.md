# Deploying ESGenuine

The public deployment is two free Render services, defined in [`render.yaml`](render.yaml):

| Service | Render type | What it serves |
|---|---|---|
| `esgenuine` | static site (free) | the React dashboard; static sites never sleep |
| `esgenuine-api` | Docker web service (free, 512 MB) | the read-only FastAPI backend |

The dashboard reads claims straight from Supabase with the publishable key and calls the
API for integrity scores, fact-checks, benchmarks and the audit trail.

**The public deployment is read-only.** The API gets no `DATABASE_URL` (sign-up, login and
PDF ingest are disabled), no service-role key and no LLM key. The publishable key is in the
public JavaScript bundle by design: row-level security grants it `SELECT` only.

**Why it fits the free plan.** The full backend holds ~340 MB because spaCy's `thinc`
imports PyTorch whenever it is installed. The public image,
[`deploy/render/api.Dockerfile`](deploy/render/api.Dockerfile), leaves out the two packages
that pull PyTorch in (`sentence-transformers`, `spacy-transformers`) — only ingest and the
`/audit/ask` Q&A use them. Every dashboard read endpoint returns 200 without it, at about
190 MB resident.

---

## Deploy

1. Render → **New** → **Blueprint** → connect this repository (grant Render's GitHub app
   access to it).
2. Render reads `render.yaml` and lists both services. Fill the values it asks for — the
   same two for each service:
   - `VITE_SUPABASE_URL` — `https://<project-ref>.supabase.co`
   - `VITE_SUPABASE_PUBLISHABLE_KEY` — the publishable (anon) key

   `JWT_SECRET` is generated by Render; the dashboard's `VITE_API_BASE` is wired to the API
   automatically.
3. **Apply.** The API image builds in a few minutes; the dashboard in about two.
4. Open the dashboard URL (`https://esgenuine.onrender.com`, or with a suffix if the name
   is taken).

Every push to `main` redeploys both services.

## Verify

- `https://esgenuine-api.onrender.com/health` → `"ready": true` (its `embedding_model`
  check reads "not installed (read-only deployment)" — expected).
- On the dashboard the header reads **Connected** and the Integrity Audit page shows a
  score, not "—". If it shows "Backend offline", the API is asleep or unreachable: open its
  `/health` URL, wait a minute, and reload.

## Operating notes

- The free API sleeps after 15 minutes without traffic; the first request wakes it in
  about a minute. Open the dashboard a minute before a demo.
- A free Supabase project pauses after a week without activity; resume it from the
  Supabase dashboard.
- Custom domain: add it to the API's `ALLOWED_ORIGINS` (comma-separated); no code change.
- Local development is unchanged: `start.bat` runs the full backend, ingest included.

## API environment variables (reference)

| Variable | Public deployment | Purpose |
|---|---|---|
| `VITE_SUPABASE_URL` | required | Supabase REST reads (claims, reports, contradictions) |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | required | read-only key for the above |
| `ENVIRONMENT` | `production` | drops the localhost CORS origins; requires `JWT_SECRET` |
| `JWT_SECRET` | generated by Render | signs login tokens |
| `ALLOWED_ORIGIN_REGEX` / `ALLOWED_ORIGINS` | set | which dashboard origins may call the API |
| `API_READ_ONLY` | `1` (set in the image) | health check does not require the embedder |
| `DATABASE_URL` | **unset** | enables accounts (sign-up/login) and therefore ingest |
| `SUPABASE_SERVICE_ROLE_KEY` | **unset** | write path; bypasses RLS |
| `NVIDIA_API_KEYS` | **unset** | LLM for the `/audit/ask` Q&A |
| `PORT` | set by Render | the image defaults to 8000 |
